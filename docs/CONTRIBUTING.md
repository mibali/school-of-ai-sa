# Contributing

Thank you for wanting to improve the School of AI SA. This curriculum is a starting point, and the community is what makes it useful.

## Ways to contribute

- **Fix an error.** AI moves fast. If a claim is out of date or wrong, open an issue or a pull request.
- **Add a lab.** Hands-on exercises are the most valuable part of each module. Labs should run on free tiers and open tools.
- **Add a worked example.** Real architectures, real trade-offs, real numbers.
- **Propose a new module.** Open an issue first so we can agree on scope before you write.
- **Improve clarity.** Shorter sentences, better diagrams, clearer examples — all welcome.

## Content standards

- Write in short sentences with active voice. Define a term before you use it.
- Every module follows the same structure: Introduction, Why this matters for the AI SA, Key concepts, A worked example, Lab, Check your understanding, Further reading, Conclusion.
- Prefer vendor-neutral explanations first, then name specific products as examples.
- Include concrete numbers where you can. "Lower latency" teaches little; "p95 under 800 ms for a chat use case" teaches a lot.
- Link to primary sources, not blog posts about blog posts.

## Review process

Every pull request gets at least one review from a maintainer. For new modules, we look for: accuracy, structure matching the template, at least one runnable lab, and further-reading links that work.

## Code of conduct

By participating, you agree to abide by our [Code of Conduct](CODE_OF_CONDUCT.md).
